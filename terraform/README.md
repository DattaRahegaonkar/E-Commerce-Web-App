# Infrastructure Using Terraform

This directory contains Terraform configuration to provision a production-ready AWS infrastructure for the e-commerce application.

## Prerequisites

- Terraform >= 1.0
- AWS CLI configured with appropriate credentials
- `baston-key` and `baston-key.pub` present in this directory

## File Structure

```
terraform/
├── provider.tf               # AWS provider (eu-west-1)
├── vpc.tf                    # VPC, subnets, IGW, NAT Gateways, route tables
├── bastion-host.tf           # Bastion EC2 instance, key pair, security group
├── install.sh                # Bastion bootstrap script (AWS CLI, kubectl, eksctl, Docker, Jenkins)
├── policy.tf                 # IAM policy for Secrets Manager access
├── eks-cluster-config.tf     # Auto-generates eks-cluster.yml and SCPs it to bastion
├── eks-cluster.yaml.tpl       # eksctl cluster config template
├── eks-cluster.yaml           # Auto-generated by Terraform (do not edit manually)
├── output.tf                 # Outputs: bastion IP, VPC ID, subnet IDs
└── baston-key / baston-key.pub  # SSH key pair for bastion access
```

## Infrastructure Components

- **VPC** — `10.0.0.0/16` with DNS support enabled
- **Subnets** — 2 public + 2 private across `eu-west-1a` and `eu-west-1b`
- **Internet Gateway** — for public subnet internet access
- **NAT Gateways** — one per AZ for private subnet outbound access
- **Bastion Host** — EC2 (`c7i-flex.large`) in public subnet with Jenkins, Docker, kubectl, eksctl pre-installed
- **IAM Policy** — `secrets-policy` allowing EKS pods to read secrets from AWS Secrets Manager (`ecommerce/*`)
- **eks-cluster.yaml** — auto-generated from template with real VPC/subnet IDs and account ID, automatically copied to bastion

## Deployment Steps

1. **Initialize Terraform:**
   ```bash
   terraform init
   ```

2. **Review the plan:**
   ```bash
   terraform plan
   ```

3. **Apply configuration:**
   ```bash
   terraform apply --auto-approve
   ```

   After apply:
   - VPC and subnets are created
   - `eks-cluster.yaml` is auto-generated with real IDs
   - `eks-cluster.yaml` is automatically copied to `/home/ubuntu/eks-cluster.yaml` on the bastion

4. **SSH into bastion:**
   ```bash
   ssh -i baston-key ubuntu@<bastion_host_public_ip>
   ```

5. **Configure AWS credentials on bastion:**
   ```bash
   aws configure
   ```

6. **Create EKS cluster:**
   ```bash
   eksctl create cluster -f eks-cluster.yaml
   ```
   > This takes 15-20 minutes.

7. **Configure kubectl:**
   ```bash
   aws eks update-kubeconfig --region eu-west-1 --name eks-cluster
   ```

8. **Verify cluster:**
   ```bash
   kubectl get nodes
   ```

## Outputs

| Output | Description |
|---|---|
| `bastion_host_public_ip` | Public IP of the bastion EC2 instance |
| `vpc_id` | ID of the created VPC |
| `public_subnet_1a_id` | Public subnet ID in eu-west-1a |
| `public_subnet_1b_id` | Public subnet ID in eu-west-1b |
| `private_subnet_1a_id` | Private subnet ID in eu-west-1a |
| `private_subnet_1b_id` | Private subnet ID in eu-west-1b |

```bash
terraform output
```

## Troubleshooting

**EKS Access Issues:**
- Go to AWS Console → EKS → Clusters → Access
- Add your IAM user with `AmazonEKSAdminPolicy`

**Node Issues:**
- Check security group rules between cluster and nodes
- Verify IAM roles have required policies attached

**eks-cluster.yml not copied to bastion:**
- Ensure bastion SSH is up and `baston-key` is present
- Re-run: `terraform apply` (null_resource will re-trigger if content changed)

## Cleanup

```bash
# Delete EKS cluster first (from bastion)
eksctl delete cluster -f eks-cluster.yaml

# Destroy Terraform infrastructure
terraform destroy --auto-approve
```
